# Known limitations and release gates

1. **Partial physical verification.** ESP32 1.1.1-dev flashing, paired pulse FIFO acquisition, LED shutdown/idle probing and real GPS communication/fix are verified. Earlier authenticated Windows/Android BLE, encrypted controls, USB/API display and short USB/BLE coexistence passed on 1.1.0-dev. Valid SpO2 was not obtained: finger signals remain algorithm-rejected. Pulse accuracy, GPS accuracy/stale-fix isolation, OLED photographs, electrical compatibility, fall jig behavior and extended coexistence/power-cycle/soak behavior still need bench work. See PULSE_FIX_1_1_1.md and CONNECT_AND_SHARE_1_1_0.md.
2. **Experimental health and alerts.** No clinical accuracy, fall-detection reliability, emergency response or safety certification. Thresholds and calibration require representative hardware data. No physiological threshold-alert rules or configurable alert-notification system are shipped.
3. **Delivery is bounded.** Firmware queues are volatile: 16 Wi-Fi packets and two BLE packets. Full queues lose new readings; power loss loses queued readings. BLE notifications may lose fragments. Alert delivery over a long outage is not guaranteed. There is no flash-backed spool or OTA updater.
4. **Firmware configuration scope.** Backend/BLE delivery interval writes work in source; device display timezone remains fixed Asia/Kolkata. OLED alerts do not mirror backend acknowledgement; acknowledgement is stored and shown by clients. Gyro calibration is RAM-only; full accelerometer/temperature calibration is pending. Motion/GPS/alert GATT projections are read views; live atomic snapshots use one framed characteristic. BLE supports one connection at a time.
5. **Background Android limits.** No guaranteed persistent background BLE monitor, foreground monitoring service or alarm notification system. Cache sync is optional and scheduled by WorkManager. Bluetooth permission denial is handled; vendor-specific power behavior needs device testing.
6. **History is bounded.** Desktop: 2,000 loaded samples / 600 chart samples; Android: 500 visible cached records across devices / 10,000 retained for seven days. Backend history returns up to 2,000 samples from a maximum 31-day received-time range. There is no cursor pagination, aggregation/downsampling service or map tile cache. Map links open OpenStreetMap only for current valid coordinates; the desktop also lists coordinate history.
7. **Preview security.** Reverse-proxy rate limiting, hosted TLS/certificate lifecycle, manufacturing secure boot/flash encryption, audit, account recovery/deletion, email verification and a security/dependency review remain release work. The supplied local HTTP configuration is development-only. Pairing/bond lifecycle needs physical review.
8. **Release signing and Windows execution.** No Android release keystore or suitable Windows signing certificate was provided. The debug APK and Windows packages are development artifacts. The local Windows installation upgrade to 1.0.2 succeeded, but Smart App Control blocks the unsigned native launcher. This protection has no individual-app approval option; trusted CA-issued code signing is required while it remains enabled. No policy was bypassed. Clean-VM install/uninstall is unverified.
9. **Design/accessibility scope.** Dark theme and English UI only. Screen-reader review, complete localization, keyboard end-to-end testing, high-contrast and large-font device testing remain pending. No custom font is bundled.
10. **Windows BLE and hosting.** A Windows BLE console monitor/backend bridge and independent USB monitor are physically tested; Bluetooth is not integrated directly into the packaged JavaFX process. No public hosting, production account service or database service installation has been performed. User-approved Wi-Fi access on port 8087 works on the actual phone, including authenticated API access and hardware sharing. Firewall rules cover local subnet and the specific phone IP; DHCP changes may require updating the rule/URL. Phone USB forwarding is also available.
11. **Environment constraints.** Windows App Control blocks the rebuilt native desktop launcher and C++ host-test executable. No policy was bypassed. JavaFX application-class tests, successful MSI upgrade, physical BLE and emulator instrumentation are recorded separately. Fresh-machine bootstrap, a clean installer VM and physical older Android versions remain unverified.

See `tests/HARDWARE_CHECKLIST.md` for the explicit outstanding hardware gates. No unavailable feature is represented by a working-looking control.
